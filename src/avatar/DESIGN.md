# Avatar builder: design

Goal: **one illustration in, an animated avatar out** (it blinks, talks, turns and tilts its head,
breathes, sways its hair), prepared by an AI agent and fine-tuned by a human dragging handles in the
editor. The output is an ordinary Rev2D model, so everything else in Rev2D works on it: sheets,
`analyze`, the editor, the web player, Spine export, Live2D motion import / export.

## 1. Project folder

```text
<project>/
  avatar.json            the avatar spec (source of truth; src/avatar/schema.ts)
  source.png             the illustration (never modified)
  <name>.r2d.json        BUILT model (regenerated by every build; customise through spec.post ops)
  textures/              BUILT layer images + layers.json (LayersMeta)
  variants/              drawn variants from an image generator: <variantId>.png, full size
  variant-requests/      <variantId>.mask.png + <variantId>.prompt.txt + README.md
  review/                pose sheets written by `rev2d avatar poses`
  work/                  scratch: grids, overlays (agent's working images)
```

User images and everything built from them stay local: nothing here is uploaded, and repositories
that hold projects should git-ignore them (the Rev2D repo ignores `projects/` and `out/`).

## 2. Pipeline

1. `parseAvatarSpec`: structural (zod) and semantic checks, giving Diagnostics with JSON pointers and
   hints (polygons inside the image, enough points, bands ordered, opening inside region, eyes on the
   right sides, landmarks inside the head ellipse, ids unique, ...).
2. `buildAvatarLayers(spec, source)`: image processing in pure TypeScript (`src/avatar/image/`),
   deterministic. The features (`src/avatar/features/`) run in a fixed order: head, body, eyes,
   mouth, brows, cheeks, hair, attachments, sprites, animations. Each one may cut layers out of the
   picture, fill the base behind them, store metadata for stage 3, and **claim** the pixels it took
   (`ctx.claim`); later features read the claimed mask to stay out of them (the hair mask never takes
   lashes or brows).
   - **base**: the source with everything that gets its own moving layer filled in behind it (see
     each feature below).
   - `layers.json` (`LayersMeta`): layer rects, the input hash, and one entry per feature (`eyes`,
     `mouth`, `brows`, `cheeks`, `hair`, `attachments`, ...).
3. `compileAvatar(spec, meta)`: pure and fast (the editor runs it on every handle drag); builds the
   Rev2D model with `ModelBuilder` (unique ids, standard parameters, explicit draw order).
4. `spec.post` ops are applied with `applyOps`, then the model is validated (`validateModel` must
   report 0 errors) and written with `formatModelJson`. The fold checker (`findFolds`) evaluates
   the extremes of every parameter and their combinations and reports flipped lattice cells as
   warnings.

## 3. The generated model

Model coordinates are source pixels (canvas = image size), so a coordinate read off the illustration
is a coordinate in the model.

### Parameters (Live2D standard ids and ranges, so Live2D motions drive avatars)

| Parameter | Range (default) | Driven by |
| --- | --- | --- |
| `AngleX`, `AngleY`, `AngleZ` | -30..30 (0) | head turn (pseudo-3D) and tilt |
| `EyeLOpen`, `EyeROpen` | 0..1 (1) | blink. `L` = the character's left = `imageRight` |
| `EyeLSmile`, `EyeRSmile` | 0..1 (0) | only with the `eyes_smile` variant |
| `EyeBallX`, `EyeBallY` | -1..1 (0) | gaze: the eyeball layer shifts inside the opening |
| `BrowLY`, `BrowRY` | -1..1 (0) | only when `face.brows` is given |
| `MouthOpen` | 0..1 (0) | mouth opening |
| `MouthForm` | -1..1 (0) | -1 narrow / round ... +1 wide / smile |
| `Cheek` | 0..1 (0) | blush opacity (only with `face.cheeks`) |
| `BodyAngleX` | -10..10 (0) | body sway |
| `Breath` | 0..1 (0) | breathing |
| `Hair_<strandId>` | -1..1 (0) | physics output per strand |
| `Sway_<attachmentId>` | -1..1 (0) | physics output per pendulum / jiggle |

Signs follow SPEC §3.1 (`AngleX > 0` = the face turns toward the screen right, `AngleY > 0` = looks
up, `AngleZ > 0` = tilts clockwise). A parameter is declared only when something drives it.

### Structure

Everything is driven by **warp lattices with additive offset bindings**: the deformations of a
single-image avatar are small, smooth displacement fields that simply add up, which is what Rev2D
warp offsets do (several bindings on one warp sum their deltas). Parts that need their own shape
(the eye mask, the mouth opening) are meshes whose vertices are keyforms.

```text
avatarWarp            the whole image as ONE lattice (cells of about 2% of the long side, at most 64)
 ├ part base          the base image as a grid mesh with the lattice's cells: head, neck and body
 │                    are one continuous mesh
 ├ bindings           headTurn (AngleX x AngleY, 3 x 3), headTilt (AngleZ, 3 or 5 keys),
 │                    bodySway (BodyAngleX), breath (Breath), att_<id>_jiggle (Sway_<id>)
 ├ cheekR / cheekL    blush ellipses (z 10), opacity bound to Cheek
 ├ per eye (eyeR = image left, eyeL = image right; z 20 .. 25)
 │   ├ eye<S>_white       mesh in the eye-white colour: underlay and mask of the eyeball
 │   ├ eye<S>_ball        the eyeball image, masked by eye<S>_white, shifted by the gaze
 │   ├ eye<S>LowerWarp    eye<S>_lower (lower lid line, lower lashes), eye<S>_lowerRim
 │   ├ eye<S>_crease      static: crease lines, eye white at the corners; fades out as the eye closes
 │   └ eye<S>UpperWarp    eye<S>_upper (the lash line), eye<S>_upperRim
 ├ mouthWarp          part mouth (an opaque crop of the mouth area, z 30)
 ├ mouthInner, mouthTongue   meshes of the open mouth (z 31, 32)
 ├ hairWarp           part hair (z 50), one sparse binding per strand; eye<S>_front (z 25): the hair
 │                    over an eye (opaque copy, its rim a matte), drawn by the eye feature
 ├ browR / browL      the brows (z 52, above the hair), shape.y bound to BrowRY / BrowLY
 ├ hair_brows         a static copy of brows NO feature cut (z 52; absent when the brows feature runs)
 └ att_<id>Warp       pendulums (z 60) and cut-outs (z 70), with rigid follow bindings
```

Why ONE lattice for head, neck and body: a single continuous mesh has no seams, and smooth weights
(the neck band) bend the neck naturally. Splitting the head into its own layer drawn over the base
looks tempting (a finer lattice for the face) but **ghosts**: wherever a silhouette inside the moving
layer shifts (the jaw line against the background, gaps between hair locks), the static copy
underneath peeks out as a double contour. Rule for every layer drawn over the base:

- either the base has been **cut / filled** under it (eyes, brows: filled; pendulums and cut-outs:
  inpainted; hair that swings over the transparent background: erased from the base),
- or the layer is an **interior patch**: fully opaque, its warp offsets vanish at its rect edge, and no
  silhouette moves inside it (the mouth area), so it always covers the base's copy completely.

Several layers are **difference mattes** (`features/eyes-matte.ts`): after the base was filled under
a drawn stroke, the layer holds per pixel the most transparent colour that turns the fill back into
the illustration. Plain skin gets alpha 0, a dark stroke a high alpha. The rest pose is the
illustration exactly, and a moving matte carries only what was drawn, never a rectangle of old skin.

**Seams.** The default renderer (2 x 2 samples per pixel, bilinear texels) blends every pixel with its
neighbours, so a pixel edge where two layers end at once is drawn twice: a stroke split pixel by pixel
between two layers, an opaque layer edge over a base that ends at the same edge, a feathered layer over
a base holding the same picture. The builders keep strokes in one layer where they can, put the base
behind a hard layer edge to what lies beside it, and give layers an opaque overlap where they meet
(the hair layer ends where the eye's copy of the hair over an eye is opaque). The check is a render of
the rest pose against the illustration drawn by the same renderer as one image
(`test/avatar-build.test.ts`, at 1024 x 1280): at most a handful of pixels differ by more than 24
levels, under 0.03% by more than 8 (single pixels where the picture has an unantialiased edge on a
layer boundary: a bang tip ending on a lid, the hair silhouette).

The generated model is large (the turn keyforms list every lattice point of the head): hundreds of
kilobytes of JSON are expected. It is a build artifact; the readable source is avatar.json.

### Head and body (bindings on the root lattice)

- **Turn** (AngleX x AngleY, keyforms at -30 / 0 / 30 of each): two domes `(1 - r^2)^e` add up. The
  face dome over the face oval (exponent 1.5) slides the features; below its centre it reaches 1.4
  face radii (mouth and chin are at the front of the head and travel with the nose), and its peak
  trails 0.1 face radii toward the side that turns toward the viewer, so the far half of the face
  compresses more than the near half stretches. The head dome over the whole head ellipse (exponent
  2) makes the hair volume follow, less and less toward the silhouette. A small Gaussian bump lets the
  nose tip lead. Everything is multiplied by the neck band, is exactly zero outside the head
  ellipse, and is scaled so that the face centre moves exactly `head.turn.x / .y` px; AngleY > 0
  moves the face up. Yaw and pitch together move 10% less than their sum.
- **Tilt** (AngleZ): a rotation about `head.pivot` whose ANGLE is weighted by the neck band times a
  fan of directions around the pivot (full within 55 degrees of straight up, none from 95 degrees):
  the strain then does not grow with the distance from the pivot, so hair and shoulders beside the
  neck are neither squashed nor lifted. Keyforms at -30 / 0 / 30, plus -15 / 15 when the arc is long.
- **Body sway** (BodyAngleX): a rotation about `body.pivot` weighted by the `body.fade` band (the head
  follows fully, the bottom rows stay).
- **Breath**: the chest dome rises by `body.breath` px and widens a little; everything above it
  rises by a third of that, the shoulder points a little more.

### Eyes (`features/eyes.ts`)

- **Layers.** The base is filled with eyelid skin under the opening and under every stroke drawn on
  the eye region (lashes, lid and crease lines with 2 px of their soft edge, and the fainter parts
  joined to them well inside the region, so a fading crease leaves no dashes); plain skin stays as it
  is. Eye white next to the opening (where the traced opening falls short) is the eye's too. The fill
  is a smooth inpaint fed by the skin and its shading around it (not by eye white or hair), so it
  meets the surrounding skin without a step. The lid layers are difference mattes against what lies
  under them at rest (the fill; inside the mask mesh the eyeball), opaque copies where the mesh
  covers part of a pixel.
- **Geometry.** The opening is grown by 1.5 px and sampled as two curves `upper(u)`, `lower(u)` over
  the image axes (an axis-aligned lattice folds when the closing direction is tilted against it).
  When the eye closes the lids meet on a gentle arc: 45% of the way from the line between the
  corners down to the lower curve. The lash band moves down rigidly onto it (upper lid warp), the
  lower lid line rises the rest of the way (lower lid warp), and the eyeball mask's two rows meet
  there, so every triangle of the mask has zero area and no eye white or iris is left. The lash band
  is the stroke joined to the opening (a double-eyelid line separated from it by skin is not); above
  it the lid lattice stretches up to the region top (the brow never moves); across the opening the
  lattice compresses linearly and never folds; the travel eases in over 15% of the width at each
  corner. Past the corners the lids do not move: the lash joined to the opening there (a flared outer
  corner) stays and the closed lash runs into it; other strokes above a corner fade out with the
  crease.
- **Eye white at the lid edges** rides on `upperRim` / `lowerRim` (they move with the lids and fade
  out between EyeOpen 0.3 and 0), eye white beyond the corners on the crease (fades from 0.45 to 0):
  a closed eye shows one lash line and no white.
- **Gaze**: `part:eye<S>_ball.shape.x / .y` shift by 3% of the opening width (up to 8.5% when the iris
  circle shows the room; 60% of that vertically; EyeBallY > 0 looks up). The ball image is continued
  beyond the opening so a shifted ball still covers the mask; the white mesh is the underlay.
- **Hair in front of an eye**: non-skin pixels that cross the region outline from far outside in tones
  that are no skin shading (deltaE >= 30 from the skin), followed inward in the hair's own tones, plus
  the lock's thin dark outline. Lash strokes joined to the opening stay the eye's, except next to a
  lock that crosses the opening, whose outline runs on through the lash line as wide as it is
  elsewhere. The hair and its antialiased rim (2 px, 3 px over the eyeball where the hair darkens it)
  are `eye<S>_front`: an opaque copy of the hair and a matte of the rim in the hair's colour over what
  the eye draws behind it. Behind them the eye layers continue the eye: the eyeball is inpainted
  under the hair, the lash line continued along the lid, the rim's backdrop continued from the eye
  next to it. The eye claims the hair only weakly (0.3): the hair layer takes it (except next to the
  rim, so its edge lies where `eye<S>_front` is opaque), the brows stay out of it, and the hair
  feature moves `eye<S>_front` into the hair warp, so the lock sways as one piece.

### Brows (`features/brows.ts`)

Per brow, the ink along the brow polyline within the brow's measured thickness (and a rounded end
drawn past the line) is lifted into its own layer (`browL` / `browR`), a difference matte against a
fill that interpolates across the brow between the pixels on both sides, along the direction within
60 degrees of the normal in which they match best: skin stays skin, a bang under the brow stays a bang
and its outline runs straight through, so a raised or lowered brow leaves no notch. Where hair
crosses the brow,
the brow's own colour decides: a brow drawn over the bangs in the hair's colour keeps its whole
line; a lock of another colour stays hair, and of the lines darker than the brow only those that run
along it (its outline) belong to it. The brows are drawn ABOVE the hair (z = hair + 2). BrowLY /
BrowRY move `shape.y`: +1 raises by 5% of the face oval's vertical radius, -1 lowers by at most half
the gap to the eye region. The eyes do not move.

### Cheeks (`features/cheeks.ts`)

Two ellipses (`cheekR`, `cheekL`, z 10) at the cheek points, 9% of the face width unless
`face.cheeks.radius` is set, wider than tall, filled with a radial gradient of a blush colour
estimated from the skin (deeper and redder in Lab); their opacity follows Cheek (0 at rest).

### Mouth without drawn variants (`features/mouth.ts`)

- `mouth`: an opaque crop of the source over the bounds of `face.mouth.area` in `mouthWarp`. All its
  motion fades out inside the area ellipse, so the patch covers the base exactly and the chin
  outline never moves.
- One binding on MouthOpen x MouthForm (keys at open 0 / 1 and form -1 / 0 / 1), in the mouth frame
  (u along the line through the corners, v across it): the skin below the closed line moves down by
  the depth of the opening (`sin(pi t)^e` along the line, 42% of the corner distance at most, and at
  most 62% of the room left below the line in the area), compressed toward the area rim; the skin
  above rises by 14% of that; the drawn line is split, its lower half becomes the lower lip line.
  MouthForm moves the corners with a Gaussian falloff: +1 out by 7% and up by 6% of the corner
  distance with a flatter, shallower opening; -1 in by 17% with a round opening.
- `mouthInner` and `mouthTongue`: strips of 17 points along the line whose vertices are keyforms on
  the same grid, built from the same curves (zero height when closed). The colours come from the
  mouth line (a deep shade of it inside, a tongue tone on the floor).
- The six lip-sync shapes of `src/lipsync` (`VISEME_SHAPES`: a, i, u, e, o, n) are review poses.

### Hair (`features/hair.ts`, `hair-mask.ts`, `hair-physics.ts`)

- **Mask**: hair tones are found under the strand polylines (k-means, without skin-like colours),
  and the mask grows from the strands through connected pixels near those tones, inside the head
  ellipse (a little larger, plus corridors around strands below the head). Claimed pixels (eyes,
  brows), brows nobody cut, cut attachments and skin are never hair; holes and the antialiased
  outline are added, so the whole silhouette belongs to the hair. `textures/hair_mask.png` shows it.
- **Layer**: the source under the feathered mask, in `hairWarp` (nested in the root lattice), plus the
  hair over the eyes (whole, but not next to the eye's rim matte) and the bangs continued under the
  cut brows (the brows feature's fill). The base keeps its copy of the hair where the moving layer
  always covers it; where a lock can swing (within the reach of its strands' swing) the base is ERASED
  next to the transparent background and FILLED by carrying the neighbouring colours inward next to
  anything else. Against seams: behind the soft silhouette the base gives up the opaque pixels next
  to the pixels it thinned, and behind a hard edge of the layer it holds what lies beside it.
- **Sway**: per strand, `Hair_<id>` moves the warp perpendicular to the strand's root-to-tip
  direction: 0 at the root, `swing` px at the tip (`t^1.5` along the polyline), a Gaussian of
  sigma = width / 2 across it. Overlapping strands add up.
- **Physics**: one group per strand, a single pendulum whose frequency comes from the strand's length
  (relative to the head) and `stiffness`, damping from its length; inputs AngleX, AngleZ and
  BodyAngleX by how far they move the strand's root; the gain is calibrated so a calm reference
  turn swings the lock to 80%; when the head tilts, a lock hangs a little toward the ground.

### Attachments (`features/attachments*.ts`)

- **Pendulum** (tassel, earring): cut into `att_<id>` with the base inpainted behind; `Sway_<id>`
  turns its warp about the pivot by up to `swing` degrees (keyforms at -1, -0.5, 0, 0.5, 1).
- **Jiggle** (bun, bow): nothing is cut; `Sway_<id>` shifts a soft ellipse of the root lattice by up to
  `swing` px, driven by a stiff, bouncy spring.
- **Cut-out** (a hand in front of the chin): cut into `att_<id>`, drawn in front of everything, the
  base inpainted behind; it moves with the body or the head (`follow`), and with a `contact` point
  that end follows the head a little.
- Pendulums and cut-outs are rigid: follow bindings replace the root lattice's bending over them by
  the rigid motion of their pivot or outline.

### Drawn variants (optional, they replace the mesh fallback where present)

An image generator redraws the eyes or the mouth of a full-size copy of the illustration; Rev2D cuts
the redrawn area out as a **sprite**. Code: `variants.ts` (flow), `variants-areas.ts` (table, edit
areas, fingerprints), `variants-text.ts` (prompts, README, preview), `variants-check.ts`,
`variants-sprites.ts` (cut, layers.json bookkeeping, status), `features/sprites.ts` (the model); file
IO and the CLI (`rev2d avatar variants request | import | status`) in `src/node/avatar-variants.ts`.

- **Edit areas** (one mask per group, at the source size: OPAQUE black = keep, TRANSPARENT white =
  may change): eye variants share both eye `region`s, grown by 8% of the region's size (sqrt of its
  area, at least 1.5 px) with a soft edge of 0.6 x that beyond; mouth variants the mouth `area`
  ellipse grown by 5% of its smaller radius. Requests write `variant-requests/<id>.mask.png`,
  `<id>.prompt.txt` (what to draw, where, and the hard constraints: same size and framing, nothing
  outside the mask changed, nothing added, same style), `README.md` and `preview.png`.
- **Check** of `variants/<id>.png`: exactly the source size; outside the mask (fully opaque mask
  pixels, the source's transparent background excluded) a mean difference of at most
  `build.variantTolerance` (default 2 of 255), at most 0.5% of pixels changed by more than 40 levels,
  and in the ring just around the edit area at most 2.5 x the tolerance (seams); a global shift (up to
  8 px) or zoom (up to 8%) is estimated from edge pixels outside the areas and named in the reason; at
  least 2% of the editable core of EACH eye (or of the mouth) must change. Differences are measured
  on premultiplied colour. A rejection carries a hint that says what to ask the generator next.
- **Sprites**: the drawing inside each edit area (alpha x editable coverage), one per eye
  (`sprite_<id>_imageLeft|imageRight`) or the mouth (`sprite_<id>_mouth`). Where layers drawn ABOVE
  the sprites cover the area at rest (hair, cut-out brows; rendered with `spriteBackdrop`), the sprite
  holds what lies under them, D = A over U solved for U, fading to the base pixel where they are
  opaque: the composite at the sprite's pose IS the drawing, and hair / brow edges are not darkened by
  a second copy. layers.json keeps them in `layers`, the accepted ids in `variants` and the
  bookkeeping under `sprites` (drawing, landmark and layer fingerprints, the check numbers, the last
  rejections). A rejected drawing never replaces an accepted sprite; a deleted drawing removes its
  sprite on the next import; a layer rebuild carries sprites over (stale ones are reported).
- **Eyes** in the model (image parts on the root warp, invisible at rest): `eyes_closed` fully shown
  up to EyeOpen 0.12, gone at 0.2; `eyes_half` fully shown from 0.3 to 0.6, gone at 0.2 / 0.7 (with a
  closed sprite it stays fully shown under it down to 0, so closed fades in over it); `eyes_smile`
  follows `EyeLSmile` / `EyeRSmile` (declared only with this sprite), on top. The hair in front of an
  eye (`<eye>_front`, moved with the hair) is lifted above the eye sprites, so it keeps swaying over a
  drawn eye; the sprites are cut with it counted among the layers drawn above them. While the sprites cover
  an eye completely its open-eye layers (white, ball, lids, rims, crease) are hidden by
  opacity bindings that subtract 1; they come back 0.02 BEFORE a sprite starts to fade, so every
  transition is a sprite fading over a fully drawn picture (another sprite or the mesh eye) and the
  skin under the eye never shows through two half-transparent layers.
- **Mouth**: `mouth_a`, `mouth_a_half`, `mouth_i`, `mouth_u`, `mouth_e`, `mouth_o` sit on the viseme
  table of (MouthOpen, MouthForm): a = (1, 0), a_half = (0.5, 0), i = (0.35, +1), u = (0.35, -1),
  e = (0.6, +0.5), o = (0.75, -1) (src/lipsync uses the same table). On a 21 x 9 grid (steps 0.05 x
  0.25) every point above MouthOpen 0.15 shows the drawn mouth nearest to it (distance in open, and
  in form x 0.5), so the nearest available sprite stands in for a missing one; at 0.15 and below the
  closed mouth of the illustration shows (a dissolve up to 0.2). Between two drawn mouths the lower
  one stays opaque while the upper one fades. With drawn mouths the mesh mouth keeps only MouthForm
  (no `mouthInner` / `mouthTongue`), so a drawn mouth never shows together with a mesh opening.
- Review poses added: the closed sprite fading (EyeOpen 0.16), smiling eyes, the drawn mouth
  fading in (MouthOpen 0.175), the half-open mouth (when drawn).

### Animations (`features/animations.ts`)

Parameter tracks only, added only when the model has the parameters they are about: `idle` (8 s
loop: two breaths, slow body sway, gentle head motion, blinks at uneven times, one glance), `blink`
(0.3 s, play it once over another animation), `talk` (2.4 s loop of open / half / closed with some
mouth form), `nod` (1.2 s), `look_around` (7 s loop), `sweep` (18 s loop through AngleX, AngleY,
AngleZ, for reviews). Every looping track ends on its first value; physics outputs are never
animated.

### Review poses (`rev2d avatar poses`)

The twelve standard poses (rest, eyes half / closed, mouth open, turn, look, tilt, sway), then those
of the features: `eyes_quarter`, `wink`, `gaze_right / left / up / down`, `brows_up / down`, `blush`,
`viseme_a / i / u / e / o / n`, `mouth_smile`, `mouth_narrow`, `hair_left / right`,
`attachments_left / right`. Poses with `zoom: 'eyes'` / `'mouth'` also appear on the magnified eye and
mouth sheets.

### Build options

`build.cell.body` sets the root lattice's cell (default 2% of the long side, raised so the lattice
has at most 64 cells per side); `build.cell.head` sets the cell of hair-sized warps (the hair warp;
default 0.6 x the body cell; there is no separate head warp); `build.cell.detail` caps the cell of the
eye and mouth warps (default 0.6% of the long side; they also use about 22 / 16 cells across the
opening / the mouth line); `build.feather` sets the soft edge of cut layers.

## 4. Quality bar (what reviews check)

- Rest pose = the illustration, pixel for pixel (max channel difference ≤ 2 outside feathered seams).
- Closed eyes: no iris or eye white left; one lash line.
- Turning ±30 and tilting do not tear the mesh, cut the chin or ears, or bend rigid accessories.
- The mouth opens without stretching the chin.
- Hair sways while face and clothing stay still.
- Deterministic: the same spec and image give the same bytes.

## 5. Tests without third-party art

The repository contains no third-party illustrations. Tests render Rev2D's own `hana` example to a
PNG and use it as the "illustration", with an avatar spec derived from hana's known geometry
(`test/fixtures` builders), and assert the quality bar numerically (e.g. the nose moves farther than
the ears at AngleX = 30; no iris-coloured pixels inside the opening at EyeOpen = 0; hair pixels move
and face pixels do not when a strand parameter changes).


## Authored arms and acting

The optional arms feature cuts authored capsules/outlines and gloves before face layers. It fills
only the torso behind a limb and clears its former exterior pixels. Separate sleeve and forearm meshes use single-bone auto weights, preserving drawn cloth and wire
width through elbow bends. The sleeve root stays behind the torso; the forearm and glove respect
the front flag. A covered elbow and sampled-colour wrist extension keep both joints connected.
Opaque overlap under the torso avoids breathing cracks; padded hand masks and pixel hulls retain
anti-aliased outlines without leaving ghost fingers. Rigid glove meshes follow hand bones. Shoulder roots share the body fields
through bindings because v1 bone parents cannot be warps. Full-body sway/bounce anchor feet or seat.
Expression patches keep existing visemes separate and discrete hand forms parent to the wrist.
No browser or Node dependency enters the feature pipeline. See docs/GESTURES.md.
